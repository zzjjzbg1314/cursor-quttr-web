# StoryAI 短期访问凭证

## 行为

长期 Cookie `music_mv_session` 仍由 D1 管理，默认 30 天，不滑动延长。
新增 HttpOnly、SameSite=Lax 的 `music_mv_access_v2`，HTTPS 下带 Secure。
凭证有效期最多 900 秒，且不超过长期会话到期时间。内容仅含版本、用户 ID、长期会话 SHA-256 和到期时间，使用 HMAC-SHA256 签名，不包含邮箱、昵称或余额。

登录、读取 `/auth/session` 及普通读取需要续期时签发新凭证，响应通过现有 Next.js 代理的 getSetCookie 转发。
普通读取凭证有效时不访问会话数据库。缺失、过期、被篡改或签名密钥轮换后，用长期会话查 D1；有效则在同一业务请求中更新 Cookie，不重发业务请求。
无长期 Cookie 时短期凭证不能单独认证。短期凭证绑定长期会话，不能用于另一账号。

所有写操作和整个 billing 控制器实时读取会话，保持撤销后不能继续支付或修改数据。`/auth/session` 也实时查询，以返回最新资料及撤销状态。公开接口、服务商回调、模板同步和渲染客户端专用认证保持各自原有机制，不强加用户登录。
普通 GET/HEAD 读取可在撤销后最多继续接受旧凭证 15 分钟；敏感操作不会走此分支。
退出时撤销 D1 长期会话并清除长期、新短期和遗留短期 Cookie。失败时不报告退出成功。并发中的响应仍可能写回旧短期 Cookie，但其不能在缺少长期 Cookie 时使用。

同进程内重叠的普通读取续期查询合并为一个进行中的任务；完成后立即移除，不增加额外缓存有效窗口。不同进程、先后错开的续期请求仍可能各查询一次，不能宣称严格每 15 分钟只有一次查询。写请求不参与合并。

## 配置与发布

设置 `MUSIC_MV_AUTH_ACCESS_SIGNING_KEY` 为独立的高熵随机密钥，至少 32 字节，所有 StoryAI 后端实例使用相同值。不要复用 Quittr、OIDC 或服务间令牌密钥，不提交密钥到仓库。
未配置时使用进程随机密钥并记录警告：单实例可工作，重启后已有短期凭证通过 D1 自动续期；多实例会相互不认签名，降低收益，所以多实例发布前必须配置共享密钥。
密钥轮换使旧短期凭证转入长期会话校验，不要求用户重新登录。
配置仅属于 `music-mv.auth`，新增组件仅在 `music-mv.enabled=true` 时启用。未修改 Quittr 认证或数据库。

## 接口自查

- 歌曲列表、详情、歌词时间轴、歌词任务读取、音色读取：复用 requireUserId。
- 素材读取、项目读取、成片记录读取和下载：复用 requireUserId / requireDownloadUserId。
- 上述模块全部 POST/PUT/PATCH/DELETE：统一实时校验。
- billing：统一 requireFreshUserId，包含 GET 余额、历史、状态和写操作。
- effectiveClientId：已登录身份采用同一机制，保留匿名标识校验和保留前缀限制。
- auth/session：实时校验；sso：签发两种凭证；logout：撤销并清除。

## 验证边界

访问凭证测试覆盖 15 分钟到期、长期到期上限、签名篡改、错密钥、跨会话绑定及异常格式。
HTTP 集成测试覆盖同请求续期、有效凭证零会话查询、真实歌曲控制器忽略伪造 client ID、写操作实时撤销、缺少长期凭证和退出清除。
前端既有 Cookie 代理、会话状态及请求包装测试验证兼容性；没有改前端文件或文案，无本地化影响。
本次修改仅影响认证，不修改渲染计划或执行，无需视频渲染或 SSIM。未进行线上实测，不能将测试中的 D1 调用次数当作线上毫秒收益。
