# Quittr 第二版缓存恢复与性能观测修正

日期：2026-11-03。基线为上一版本地提交 `691be98`。本版不部署，不调用线上写接口。

## 实际修正

对文章分页／按类型分组（中文、国际版）、冥想视频（中文、国际版）、视频场景（中文、国际版）、白噪音、纯音乐、激励视频分页／完整列表，共 12 个缓存方法增加失败结果排除条件。保留原有字段、HTTP 状态、缓存名称、参数键及服务层更新失效规则。

修复前故障注入：19 个控制器缓存方法中，12 个在服务恢复后仍返回缓存失败结果；另 7 个能够恢复。修复后扩展覆盖到 19 个控制器缓存方法及 2 个应用屏蔽计划服务缓存方法，验证首次故障、下一次恢复、成功命中以及清除后重新获取。测试使用真实 Spring 缓存拦截器和模拟服务，不连接生产数据库。

性能日志区分 success、business_failure、http_failure 和 exception。HTTP 200 包装的业务失败不再被记作成功；保留原返回对象及原异常。每条记录增加内部 traceId、单调时钟耗时、当前线程同步 D1 query 次数、失败次数及累计耗时。日志不新增 SQL、参数、令牌、异常正文或用户响应正文。请求结束清理上下文，嵌套调用恢复外层上下文。

## 指标边界

- durationMs 为控制器调用链耗时，不含完整网络传输、序列化或压缩耗时。
- d1QueryCalls／d1QueryFailures／d1QueryMs 仅统计 CloudflareD1Util.query 路径，包含其网络等待及解析；不统计独立写入、批处理、其他直接 HTTP 路径、工作线程异步查询或 HttpClient 内部重试次数。
- responseStatus 从 ResponseEntity 推导；普通返回值默认 200，抛出的异常标为 unresolved，不宣称是最终 Servlet HTTP 状态。
- traceId 为此调用的内部日志关联标识，没有改变响应协议，也没有传递给 D1 或 App。
- 当前未增加缓存命中率、连接池等待或 SQL 内部执行时间指标；不能把 D1 查询数为零直接判定为缓存命中。
- 观测本身不提速；它帮助上线后依据实际数据选择下一项优化。

## 验证与复跑

```sh
python3 docs/qa/quittr-backend-reliability-2026-11-03/run_regression.py --output /tmp/quittr-reliability-new-run
```

要求 Java 8、Maven，输出目录不存在或为空。沿用独立编译目录，不加载生产配置；压缩测试仅在本机随机端口启动合成响应服务。汇总见 test-summary.json，修复前证据见 before-cache-summary.json，逐接口前后对照见 contract-comparison.json。

覆盖范围：21 个缓存恢复用例、5 项观测用例、上一版 10 项性能／缓存测试及 2 项压缩测试，另有 504 个路由解析断言和 504 次真实控制器＋模拟依赖请求。观测用例检查业务／HTTP／异常分类、原结果与异常透传、真实 query 逻辑的成功及两类失败、没有额外 HTTP 请求、无上下文时的行为，以及嵌套／线程复用时的上下文清理。

开发中修正了两处测试夹具问题：源代码使用完整注解名的音乐缓存方法也需计入，实际控制器缓存数为 19；服务实现类需使用类代理才能按实现方法反射调用。测试夹具错误没有当作产品问题。

## 剩余边界

未完成生产数据库 CRUD、手机端到端验收或线上性能 A/B。缓存更新后的真实数据库链路仍需在测试环境验收；本轮直接清除缓存验证重新获取。部署重启才会清除旧进程中已经缓存的失败对象。

本版没有更改登录／权限协议、写重试、分页上限或 SQL 索引；这些仍需前后端兼容方案或真实查询指标。没有修改共用后端的网站接口、文案或语言处理规则。原有歌词、歌曲导入及特效未提交改动保留，不纳入此提交。按仓库要求创建本地中文提交，不自动推送。
