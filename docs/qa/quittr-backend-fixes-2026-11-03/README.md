# Quittr 后端首批体验修正与验证

日期：2026-11-03。基于上一轮调研，本版修改三个明确问题；未部署、未调用生产写接口、未修改 App。

## 改动和可验证收益

| 改动 | 实现 | 已验证的预期 |
| --- | --- | --- |
| 视频列表不缓存失败 | 国际版、中文版 Cacheable 排除非 2xx、空正文和业务失败结果；原缓存键与服务层写入失效逻辑保留 | 第一次 500 不进入缓存，第二次恢复成功，第三次命中成功缓存；清除后可重新获取；中文键不与国际版冲突 |
| 个人帖子批量统计 | 复用既有点赞和评论批量方法，按 90 条分组；保留 DTO、翻译、排序和原列表查询 | 10 条帖子额外统计调用由 20 次变为 2 次；0 条无统计调用；大分页不截断、不构造过多参数 |
| JSON 传输压缩 | Spring Boot/Tomcat 内置压缩，application/json，阈值 2KB；SERVER_COMPRESSION_ENABLED=false 可关闭 | 本地真实 HTTP 服务正确协商 gzip；解压后字节完全一致；小 JSON、事件流和媒体响应不压缩 |

批量统计将常见一页的数据库访问路径从约 1+2N 降为约 3 次；超过 90 条时为 1+2×ceil(N/90)。这是源码与隔离调用次数证据，不是生产延迟承诺。尚未测真实 D1 数据规模下的耗时。

压缩配置作用于本服务所有符合条件的 JSON，包括共用此后端的网站接口，不仅是 Quittr 的公开接口；不更改字段或语言。测试载荷包含十种语言的文字，逐字节验证内容不变。未做网站十语言真实用户流程验收。不开启 HTML、事件流或媒体压缩，也不重新编码图片和视频。

## 本地验证结果

使用独立 Maven 输出目录编译所有主代码，不加载整个生产应用，不连接 D1、支付、推送或其他真实业务服务。压缩验证仅在 127.0.0.1 随机端口启动带合成响应的 Tomcat，绑定仓库中实际 server.compression 配置，不启动业务控制器或额外连接器。

- 504 个路由解析断言：通过。
- 504 次真实控制器＋模拟服务冒烟：已执行；按方法、路径、内容协商和 handler 对齐，与历史记录完全一致。这里不将模拟 400/500 当成真实业务成功或缺陷。
- 10 项性能／缓存回归：通过。个人帖子覆盖 0、1、10、50、90、91、1000 条；逐项比较全部 DTO 字段、翻译、顺序及统计值，验证缺失统计为零，验证既有评论批量 SQL 保留删除过滤。
- 2 项压缩回归：通过。每项覆盖 4 种响应和 3 种 Accept-Encoding，共 24 次本地 HTTP 请求；涵盖 gzip、identity、gzip;q=0、关闭开关、Vary 及解码一致性。
- 没有新增线上请求，没有修改生产数据。

上述断言全部通过，不代表真实数据库 CRUD、全部用户角色或手机端到端验收。没有依据承诺“绝对不会引入新问题”。现有服务层缓存清除注解未改动；本次缓存回归直接清除缓存验证重新取数，未执行真实内容更新后写数据库的整条链路。

## 复跑

在后端仓库根目录执行：

```sh
python3 docs/qa/quittr-backend-fixes-2026-11-03/run_regression.py --output /tmp/quittr-fixes-new-run
```

要求 Java 8、Maven，输出目录不存在或为空。脚本复用上一轮的路由、控制器冒烟测试，运行本目录新增的验收断言，不运行旧报告中“复现旧缺陷即通过”的历史行为测试。旧报告及其原始证据保留作为修复前基线。

本轮运行输出：`/tmp/quittr-fixes-regression-20261103`。脱敏用例统计见 `test-summary.json`，接口对照结果见 `contract-comparison.json`。原完整控制器记录在本机临时输出目录中。

## 范围、上线和回退

未处理 Google 身份验证、写接口归属、写请求重试／幂等、分页上限和错误协议。这些仍是调研中的待办，尤其身份与权限问题不能因本版性能修复通过就视为解决。

上线前还需在测试部署验证代理层压缩与 Android/iOS 解压、真实个人帖子统计值、实际更新内容后缓存刷新；上线后再比较延迟、错误率、CPU 和响应字节。压缩可通过环境变量关闭，其他两项可独立回退相应改动。生产 Caffeine 为进程内缓存，部署重启应清除旧进程中已经缓存的失败对象；未重启的旧实例仍保留旧行为。
