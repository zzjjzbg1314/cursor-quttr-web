## 实测结果

### 42 照片绑定项目

使用新建的两个隔离测试账号/短期会话、43条合成素材元数据，其中42条属于主测试账号、1条属于另一个账号。没有读取现有用户的会话、没有上传虚构图片到R2，也没有把这次元数据测试描述成媒体上传/完整导出验收。

- 三次连续成功 PUT：**2221.0 / 2003.5 / 2014.2 ms**。
- 重复使用同一照片于不同槽位的成功 PUT：2133.5 ms。
- 新性能日志确认成功保存 **7 次 D1 请求（含会话查询）**；业务路径为6次。旧代码42个绑定是约89次业务往返（代码核算），旧路径未在本次重新运行，不能虚构原耗时。
- 数据库耗时占接口绝大部分：例如2005 ms请求中，D1约1995 ms。说明下一步要继续优化往返或部署距离，而非只调整页面加载提示。
- 读取后42个槽位、照片顺序、裁剪x/y/zoom和revision正确。
- 另一个账号读取404、写同一项目409；旧revision409；混入另一账号素材400；失败后已保存revision仍为3。
- 删除成功后再读取404。

**当前约2秒，尚未达到此前建议的1.5秒目标。** 这是本地低并发抽样，不是P95或生产性能保证。

### 索引

当前D1真实计划：

- 项目列表 → idx_music_mv_projects_recent_active，无临时排序。
- 最近素材 → idx_music_mv_assets_recent_active，无临时排序。
- 完成视频列表 → idx_music_mv_render_jobs_owner_completed，无临时排序。
- 本地SQLite另外覆盖未筛选状态的视频列表，使用归属时间索引，无临时排序。

这证明排序路径改善，不代表在千/万条用户数据时已完成容量验收。

## 回归范围和结果

1. 网站后端当前源码对应 **63个测试类、408项Java测试全部通过**。覆盖控制器、会话/权限、项目、素材、模板、歌词、音色、歌曲、浏览器渲染任务协议、对象存储和支付隔离测试。没有运行无关旧Mac渲染矩阵。
2. 项目快照真实SQLite用例覆盖42素材事务写入、旧修订拒绝、外部账号拒绝；原11个模板版本绑定场景仍通过。
3. 4种核心列表索引执行计划检查通过；变更的Python测试夹具均通过py_compile。
4. 23次真实本地HTTP回归请求按预期返回，包括成功和权限/冲突拒绝；所有断言通过。
5. 歌词草稿编辑、历史读取、列表剔除历史、恢复旧歌词、跨账号拒绝通过真实接口验证。没有重新生成付费歌曲。
6. 歌词并发轮询合并、上游错误不缓存及跨账号隔离通过服务测试；音色验证到ready及跨阶段刷新通过现有服务测试。供应商使用测试替身，没有消费新的生成额度。
7. 15次公开GET复测通过；新建测试账号、会话、项目、素材元数据、歌词草稿已在finally清理，原作品不动。
8. 本地8080已重启并加载优化；重启前确认没有近期执行中的渲染任务，原浏览器登录会话未主动注销。

首次完整测试出现两类问题，已定位后修正再通过：默认照片裁剪夹具仍模拟旧单张查询，改为现有批量媒体查询并继续断言裁剪值；模块关闭场景缺少组件条件，补齐开关。另有745个带“数字副本”后缀的旧编译文件干扰扫描，已从target移到 `/tmp/perf-duplicate-bytecode-quarantine` 保留，并非删源码。

## 仍未闭环的结构性建议

本轮不是前一报告所有中长期建议的全部落地。为了保持现有流程，本轮未直接切换以下协议/存储方案：

- 模板COUNT与列表合并批次、分类缓存、全文搜索和大数据分页；仍有串行远程请求与复杂搜索开销。
- 渲染状态/场景会话拆分、用户素材R2归属元数据批量/受控并发；现有准备与导出协议保持不变。
- 歌词结果跨实例持久化及验签回调消费、AI提交任务化；本次缓存仅单实例、重启丢失，供应商查询作为回源。
- 浏览器到R2素材直传、媒体代理链路改造；仍需专项验证CORS、Range、取消、文件真实性和归属。
- 所有端到端deadline统一。D1不再等待120秒，但歌曲供应商仍有120秒配置，前端部分55秒预算仍需下一轮任务化改造；没有掩盖为已全部解决。
- 支付状态中的Stripe实时订阅查询未改成可能过期的缓存，未做真实支付/退款测试。

本次没有新跑真实歌曲生成、完整视频渲染/导出或SSIM，也没有新增浏览器视觉验收。改动是API查询、缓存、索引和观测，没有更改渲染算法、场景资源或输出参数；已有渲染任务协议测试通过，但不能等同于真实成片验收。生产并发容量、P95/P99和弱网长时间测试也尚未执行。
