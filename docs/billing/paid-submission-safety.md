# 付费提交保护（2026-10-01）

## 不变量

- 状态查询、回调与恢复不调用歌曲提交接口；HTTP 客户端继续禁用自动重试。
- 歌曲请求使用用户和 requestId 唯一约束。只有明确拒绝才释放额度；HTTP 故障、无法解析、缺少任务编号和非预期异常均保留未知结果。
- 服务商提交后的数据库保存、事件写入独立执行，失败不得释放额度或再次提交。
- 歌词提交先用数据库唯一键占用，再调用服务商。占用不设自动过期，不因重启、重试或另一个节点接手而重新提交。已有结果返回原任务句柄；输入不同拒绝；未知结果保持占用。
- 前台歌曲与歌词使用独立持久化请求编号。歌词响应丢失、接口异常或缺少任务句柄时保留编号，禁止静默更换输入重新生成。

## 部署顺序

1. 在网站实际使用的 D1 数据库执行 `src/main/resources/db/music-mv-lyrics-submission-migration.sql`，不要执行完整初始化脚本。所有后端节点必须使用同一业务数据库，并确认歌曲表已有 `(user_id, request_id)` 唯一约束。
2. 更新全部接收网站请求的后端节点，避免请求落到旧版本。
3. 更新前台。旧页面的歌词请求缺少 requestId 会被拒绝，刷新页面后再操作；不允许缺少编号时回退为不去重提交。
4. 不允许回滚到不支持去重的后端继续接收付费请求。保留占用表和已有记录。

## 未知结果的处理边界

占用不自动删除。歌词在服务商已受理但本地未保存句柄的情况下，需要人工核查服务商任务记录后恢复原任务；当前没有自动对账或管理恢复界面。不能以清空浏览器记录、删除数据库占用或释放额度作为恢复手段。歌曲沿用已签名回调补全未知任务的机制。

保护按一次请求编号生效，不把用户明确发起的不同请求合并。线上代理设置、数据库迁移执行结果及服务商账单需上线时另行核对，本轮未访问生产数据库，也未触发真实生成。

## 验证

后端针对生成、服务商、歌词、计费与新增安全边界共 45 项模拟测试通过。前端类型、本地化检查及 5 项请求恢复测试通过。SQLite 执行迁移两次并验证重复占用和用户隔离通过；不等同于已在生产 D1 执行迁移。
