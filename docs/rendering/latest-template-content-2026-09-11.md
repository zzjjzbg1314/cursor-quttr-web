## 数据库提交阶段的新旧顺序保护

仓储 publish() 将新旧顺序判断放入更新当前内容指针的 SQL 条件中：目标属于同一模板且 browser_ready，目标必须比提交时的当前内容更新（或是当前内容的重复提交）。随后仅把当前指针选中的目标标记为 published，并在同批操作末尾读取实际当前内容；仓储返回是否选中目标，服务在失败时明确报告 TEMPLATE_PUBLICATION_SUPERSEDED，避免迟到请求返回发布成功。

8 项聚焦检查通过：6 项服务和原生场景检查，加 2 项通过 H2 内存数据库执行生产 SQL 的检查。覆盖较新请求先提交、较旧请求先提交两种顺序，旧请求迟到不能覆盖；目标缺失、不就绪、属于其他模板、模板已删除或当前内容已失去就绪状态时拒绝。H2 使用项目既有测试依赖，没有增加生产数据库依赖。

验证限制：上述顺序测试覆盖竞争请求先后落库的结果，不是云端 D1 的同时请求压力测试。没有执行线上发布，没有启动渲染或 SSIM。运行中 8080 仍未加载本轮改动。历史记录和无引用资源清理尚未实施，整个单份正式内容目标未完成。

## 旧素材清理按具体引用判定

已有 TemplateMediaCleanupService 对队列中的旧素材执行引用检查，但旧仓储查询把同一模板的任意项目/任务都计作引用，导致新内容上的项目也阻止旧素材清理。本次按具体内容绑定及显式素材引用判定：保留同一旧内容的项目和任务、内容绑定未知的项目、任意项目 draft_json 或任务 request/result/evidence 中引用该素材的记录，以及场景和媒体表直接引用。缺少旧内容标识或查询证据不足时仍保留。

14 项检查通过：6 项发布及原生场景、3 项实际 H2 SQL、5 项清理服务。新增 SQL 用例确认新内容绑定本身不误占用旧素材，各类直接引用和未知绑定阻断清理。清理服务测试仅使用模拟 provider，验证检查引用先于删除以及失败重试，没有实际删除云端素材。

范围：该改动作用于已有旧素材队列；尚未把整个旧内容记录及运行包加入自动淘汰，也未删除版本表记录。8080 未加载本轮改动，未运行渲染或 SSIM。单份正式内容策略仍未完成。

## 项目保存与旧内容淘汰的绑定保护

项目原先先验证再无条件 UPSERT 模板绑定，存在验证后旧内容被清理、仍写入失效标识的间隙。本次将绑定存在性放进 MusicMvProjectDraftRepository.saveSnapshot() 的 INSERT SELECT 条件：无模板选择时正常保存；新绑定只允许模板当前内容；已有项目可继续保存其原绑定，但目标内容必须仍存在且模板未删除。未满足条件时不写项目，后续照片关联更新继续受原有写入标记与修订号保护。

5 项项目保存检查通过，其中一个用例捕获生产生成的 SQL 和参数，通过 Python 标准库 SQLite 实际执行七种情形：当前内容、旧内容、已有旧绑定、目标不存在、无选择、不完整选择、已有绑定目标被删除。最后一种确认失败不更改旧项目也不删除照片关联。其余四项验证原项目服务的修订号、授权等行为。Python 语法检查通过；测试未增加生产依赖。

没有操作真实项目、渲染任务或云端数据库。没有删除历史记录，8080 尚未加载改动；未运行渲染或 SSIM。该保护是自动淘汰旧内容的前置条件，淘汰流程本身仍未接入。
