# 模板仅使用最新正式内容

用户最新要求：每个模板只保留最新验收并发布成功的正式内容，不再长期保留历史回退。更新期间的临时输入与被项目、进行中任务引用的数据不能直接删除。

本次在 MusicMvTemplateCatalogService.publish 增加入口校验：存在不同当前内容时，目标顺序必须严格更新；旧内容、相同顺序的不同内容或缺失顺序明确拒绝。首次发布及重复提交当前内容仍走原有能力、运行包、场景和 SSIM 证据校验。

6 项聚焦测试通过，其中发布正例覆盖首次发布、更新替换、当前内容重复提交；负例覆盖旧内容、重复顺序、缺失顺序及验收场景不匹配；另验证原生曲速与非线性场景保存读取和缺失时钟阻断。

范围限制：这是服务入口检查，数据库并发切换的原子保护尚未实现。没有清理历史行或资源，没有移除版本表，没有修改项目绑定。运行中的 8080 尚未加载该改动；未 push、未运行渲染或 SSIM。整体单份正式内容策略尚未完成，不能以此宣称所有并发发布均已满足最新优先。

## 数据库提交阶段的新旧顺序保护

仓储 publish() 将新旧顺序判断放入更新当前内容指针的 SQL 条件中：目标属于同一模板且 browser_ready，目标必须比提交时的当前内容更新（或是当前内容的重复提交）。随后仅把当前指针选中的目标标记为 published，并在同批操作末尾读取实际当前内容；仓储返回是否选中目标，服务在失败时明确报告 TEMPLATE_PUBLICATION_SUPERSEDED，避免迟到请求返回发布成功。

8 项聚焦检查通过：6 项服务和原生场景检查，加 2 项通过 H2 内存数据库执行生产 SQL 的检查。覆盖较新请求先提交、较旧请求先提交两种顺序，旧请求迟到不能覆盖；目标缺失、不就绪、属于其他模板、模板已删除或当前内容已失去就绪状态时拒绝。H2 使用项目既有测试依赖，没有增加生产数据库依赖。

验证限制：上述顺序测试覆盖竞争请求先后落库的结果，不是云端 D1 的同时请求压力测试。没有执行线上发布，没有启动渲染或 SSIM。运行中 8080 仍未加载本轮改动。历史记录和无引用资源清理尚未实施，整个单份正式内容目标未完成。
