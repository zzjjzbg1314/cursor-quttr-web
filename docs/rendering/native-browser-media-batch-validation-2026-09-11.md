# 浏览器任务资源批量交付验证 · 2026-09-11

本次修复出帧前后端交付资源的逐项数据库查询，不修改 nativeEngine、效果、时间线、图片绑定或验收标准。适用于所有通过同一浏览器任务接口导出的模板。

## 已确认原因与修改

`MusicMvRenderJobService.browserRenderView` 原来在循环内按默认照片和场景资源逐项查询 D1。任务详情就绪时和领取渲染任务时均会调用此路径；准备校验阶段已有的默认照片批量读取没有覆盖这里。

现在先收集本次契约实际需要的媒体角色，去重后通过一个 D1 批请求读取，按角色映射回原顺序。每条 SQL 最多 80 个媒体角色，避免大量资源超出绑定参数限制。无数据库依赖时不发查询；内联资源和独立精确图片保留原交付路径。版本限定、音乐所有权、场景能力检查、默认图与资源就绪检查全部保留。数据库 `(version_id, media_role)` 唯一约束保证映射无歧义。

本次没有合并全部后端接口，也没有增加跨请求缓存或延长资源签名有效期。

## 只读数据库证据

对上次诊断任务的实际 8 张默认照片、7 项数据库资源读取相同字段：15 次串行查询共 22.3111 秒，单次集合查询 1.0796 秒，所有返回媒体字段逐项相等、无重复角色。

这是一次独立 Python HTTP 查询测量，包含网络及连接开销；不能直接等同于 Java 连接池请求耗时，也不能声称完整导出节省了 21 秒。代码及测试确定的是资源查询由逐项 HTTP 往返变成一次批请求。
