# 编辑页面首次加载优化（2026-09-11）

进入编辑页需要先取得模板详情，再准备原生预览。此前模板详情请求实测约 9.54 秒，接近前端 10 秒超时；刷新缓存只能帮助短时间重复进入，不能解决首次请求。

## 已修改

- 最小运行依赖清单存在时，不再查询已经退役的完整运行包记录。
- 场景中的精确图片按资产哈希合并查询，同一图片用于多个绑定只查询一次，输出保留原始顺序和各自类型。
- 保留资源就绪状态、类型、哈希与大小校验；缺少图片仍明确失败。保留模板权限、发布状态及版本检查。
- 同步修正已有晋升测试夹具：显式设置照片槽位列表，符合当前 DTO 的必填约束。

## 验证

90 项相关 Java 测试全部通过。覆盖重复图片不同用途、批量查询次数、源资源缺失、尺寸不符、目录消费者绑定顺序及最小依赖跳过旧包查询。实际 Chrome 编辑页能够完成准备、显示画面和播放入口。

此 28 槽模板的远程查询由 6 次减少到 4 次。最终代码重启后，首个模板版本详情请求为 **4.563 秒**，HTTP 200，响应 5,233,876 字节。与本次前一次返回比较，除到期签名 URL 外契约相同。另两次冷请求观察为 9.673 秒、4.946 秒，说明远程网络仍有明显波动，不能据此宣称所有首次加载稳定提速一半。

临时分段计时显示：一次 4.946 秒请求中，主场景查询占 3.325 秒（约 367 万字符），版本查询 0.722 秒，运行依赖查询 0.361 秒，精确图片批量查询 0.306 秒。临时探针已移除。

接口耗时不等于整页加载耗时。此次没有改变 SDK、原始场景、资源字节、图片解码或帧执行方式，因此执行相关服务测试与实际页面检查，未重复完整视频渲染或 SSIM。首次场景传输与原生预览准备仍是后续优化空间。
