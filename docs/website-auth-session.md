# 网站短期身份凭证

## 配置和上线

网站前端仓库为 `/Users/zongjei/Documents/code/capcut`。本次前后端版本必须配套发布。

通过 `MUSIC_MV_AUTH_ACCESS_SIGNING_KEY` 提供独立的随机签名密钥，至少32字节随机材料（可使用URL安全Base64编码）。所有实例和地区使用相同密钥。缺失或过短时启动失败，不使用默认密钥，不复用其他服务密钥。

本地开发可使用 `secrets/music-mv-auth.properties`，设置 `music-mv.auth.access-signing-key`，权限600。Spring可选导入该文件；目录已被Git忽略，不提交密钥。线上使用部署环境变量或受控配置文件。

无需数据库迁移。原有 `music_mv_session` 长期登录保持兼容；登录或 `GET /auth/session` 会设置120秒的 `music_mv_access`，并返回 `accessExpiresAt`。两个Cookie均为HttpOnly、SameSite=Lax，HTTPS为Secure。

## 验证和失效

普通受保护接口本地验证HS256签名、JWT类型、签发方、使用范围、用户、会话、签发/到期时间，以及长期Cookie的SHA256绑定。短期有效期不能超过长期会话到期时间。不信任客户端工作区ID，不缓存余额或业务权限，业务所有权和扣费规则继续执行。

无有效短期凭证但带会话Cookie时，在业务执行前返回401和 `AUTH_ACCESS_EXPIRED`。前端统一续期后最多重试一次，必须保留生成幂等编号。原生视频播放和下载在短期凭证失效时验证长期会话，避免无法执行JavaScript续期的媒体请求失败。

会话接口始终查询有效长期会话和当前用户状态，并按原有5分钟规则更新活动时间；续期不延长长期会话。注销撤销长期会话，并独立清除两个Cookie。除当前浏览器清除Cookie外，已泄露的完整凭证对或用户封禁最多有120秒失效窗口；没有即时撤销黑名单。

前后端同时回退即可恢复原有鉴权。签名密钥轮换会使短期凭证失效，但有效长期会话可以重新换取凭证。旧前端不能在新后端上长期保留，发布后刷新已有页面。
